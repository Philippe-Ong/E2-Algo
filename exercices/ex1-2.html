Factorielle : boucle, récursion et table

Calculer n! de trois façons et afficher les vingt et une valeurs de 0! à 20! sans déborder.

Ce que demande l’exercice

L'exercice demande une fonction qui calcule la factorielle d'un nombre passé en paramètre, appelée depuis main, et l'affichage par printf des factorielles de 0 à 20.

a) Une version itérative. b) Une version récursive. c) Une version qui lit une table calculée par le préprocesseur.

La note de l'énoncé conseille unsigned long long et le format %Ilu pour viser plus grand ; la sortie du cours vient d'une exécution Windows et montre les 21 lignes, de 1 à 2 432 902 008 176 640 000.

théorie nécessaire

Les notions à mobiliser

Le cas de base

Une récursion a besoin d'une porte de sortie : 0! et 1! valent 1, donc if (n <= 1) return 1;. Sans ce test, l'appel descend indéfiniment et la pile d'appels déborde.

La pile d'appels

fact(20) empile 21 trames, une par valeur de 20 à 0, puis les dépile en multipliant. Le coût est linéaire : n multiplications et n + 1 appels, en O(n) temps comme en O(n) mémoire.

La table précalculée

Le préprocesseur ne calcule rien : il substitue #define F5 (F4 * 5ULL). C'est le compilateur qui évalue les vingt produits une fois pour toutes ; la lecture suivante est un simple accès indexé, en O(1).

03
méthode

Comment procéder

  1. Poser l'accumulateur à 1 et la boucle de 2 à n, pour que 0! et 1! passent sans multiplication.
  2. Écrire la récursion avec le cas de base n inférieur ou égal à 1 et le retour n × fact(n−1).
  3. Construire la table par #define en chaîne, de F1 à F20, puis l'indexer avec un tableau const.
  4. Afficher avec %llu et un argument unsigned long long, jamais avec %d.
  5. Comparer les trois sorties ligne à ligne, puis tester 21 pour voir le débordement.

application

Application à l’énoncé

exemple.cC11
/* a) itération */
unsigned long long factIteration(unsigned n)
{
    unsigned long long acc = 1ULL;
    for (unsigned i = 2; i <= n; i++) {
        acc *= i;
    }
    return acc;
}

/* b) récursion : n! = n * (n-1)! */
unsigned long long factRecursion(unsigned n)
{
    if (n <= 1u) {
        return 1ULL;          /* cas de base : 0! = 1! = 1 */
    }
    return n * factRecursion(n - 1u);
}

/* c) table construite par le préprocesseur */
#define F1  1ULL

#define F3  (F2 * 3ULL)

#define F7  (F6 * 7ULL)
#define F8  (F7 * 8ULL)

#define F12 (F11 * 12ULL)
#define F13 (F12 * 13ULL)
#define F14 (F13 * 14ULL)

#define F17 (F16 * 17ULL)

    1ULL, F1, F2, F3, F4, F5, F6, F7, F8, F9, F10,

unsigned long long factLut(unsigned n)
{
    return (n < eFactLutLen) ? cFactLut[n] : 0ULL;
}

Le temps ne se lit pas au chronomètre sur vingt valeurs : les trois versions rendent la même chose en microsecondes. Ce qui les sépare est le nombre d'opérations. Sur cinq millions d'appels mesurés ici avec clock_gettime, sans optimisation et avec gcc 13.2, la boucle et la récursion prennent 25 à 30 ns par appel, la table 0,8 ns : une trentaine de fois moins.

Résultat. Les trois versions donnent les mêmes 21 valeurs. 20! = 2 432 902 008 176 640 000 est le plus grand factoriel qui tient en 64 bits.

erreurs fréquentes

Les pièges

À vérifier
  • Initialiser l'accumulateur à 0 : tous les produits restent nuls et 0! vaut 0 au lieu de 1.
  • Calculer en int 32 bits : 13! = 6 227 020 800 dépasse déjà 2 147 483 647.
  • Afficher un unsigned long long avec %d : format inadapté ; utiliser %llu.
  • Croire que la table évite le débordement : 21! = 51 090 942 171 709 440 000 dépasse 2⁶⁴ − 1, et la multiplication rend 14 197 454 024 290 336 768.
